# 2026-09-10 학습 정리

## Spring Boot 배포 설정

오늘은 기존 게시판 프로젝트와 별도로 `deployment` 프로젝트를 생성하고, Spring Boot 애플리케이션을 **JAR/WAR 형태로 배포할 수 있도록 설정**했다.

### 1. Gradle WAR 플러그인 추가

`build.gradle`에 `war` 플러그인을 추가했다.

```gradle
plugins {
    id 'java'
    id 'war'
    id 'org.springframework.boot' version '4.1.1'
    id 'io.spring.dependency-management' version '1.1.7'
}
```

WAR(Web Application Archive)는 웹 애플리케이션을 서버에 배포할 때 사용하는 패키징 형식이다.

### 2. Spring Boot 버전 및 프로젝트 버전 설정

Spring Boot 버전을 `4.1.1`로 설정하고 프로젝트 버전을 `1.0.2`로 변경했다.

```gradle
version = '1.0.2'
```

### 3. Tomcat 의존성 설정

외부 Tomcat 환경에 배포할 수 있도록 Tomcat을 `providedRuntime`으로 설정했다.

```gradle
providedRuntime 'org.springframework.boot:spring-boot-starter-tomcat:4.1.1'
```

애플리케이션을 WAR로 만들어 외부 Servlet 컨테이너에서 실행할 때 필요한 설정이다.

## SpringBootServletInitializer

외부 Tomcat에서 Spring Boot 애플리케이션을 실행하기 위해 `ServletInitializer`를 추가했다.

```java
public class ServletInitializer extends SpringBootServletInitializer {

    @Override
    protected SpringApplicationBuilder configure(SpringApplicationBuilder application) {
        return application.sources(DemoApplication.class);
    }
}
```

기존의 `main()` 메서드로 직접 실행하는 방식과 별개로, 외부 Servlet 컨테이너가 Spring Boot 애플리케이션을 시작할 수 있도록 연결해주는 역할을 한다.

```text
외부 Tomcat
    ↓
ServletInitializer
    ↓
DemoApplication
    ↓
Spring Boot 애플리케이션 실행
```

## Profile

스프링에서 제공하는 **Profile 기능**을 이용하면 실행 환경에 따라 여러 개의 설정 파일 및 설정 클래스를 작성하고, `spring.profiles.active` 프로퍼티 설정에 따라 필요한 프로파일을 선택적으로 활성화할 수 있다.

예를 들어 개발 환경과 테스트 환경을 분리하여 각각 다른 데이터베이스나 설정을 사용할 수 있다.

또한 프로파일은 `application.properties`의 설정뿐만 아니라 **환경변수나 프로그램 실행 옵션**을 통해서도 지정할 수 있다.

```properties
spring.profiles.active=dev
```

`dev` 프로파일을 활성화하면 `application-dev.properties`와 같이 해당 프로파일에 맞는 설정을 사용할 수 있다.

## Profile을 이용한 개발 환경 초기화

`DataInitializer`를 생성하고 `@Profile("dev")`를 적용했다.

```java
@Component
@Profile("dev")
public class DataInitializer implements ApplicationRunner {
    // 초기 데이터 저장
}
```

`dev` 프로파일에서만 실행되도록 하여 개발 환경에서 필요한 초기 회원 데이터를 자동으로 저장하도록 구성했다.

```text
dev 프로파일
    ↓
DataInitializer 실행
    ↓
MemberRepository
    ↓
회원 초기 데이터 저장
```

## 애플리케이션 빌드

Spring Boot 프로젝트를 생성할 때 `Spring Web` 의존성을 포함한 웹 애플리케이션을 **외부 Servlet 컨테이너에 배포**해야 한다면 `WAR(Web Application Archive)` 파일로 패키징해야 한다.

Gradle에서는 `war` 플러그인을 추가하고 외부 Tomcat에서 실행할 수 있도록 설정한다.

```gradle
plugins {
    id 'war'
}
```

즉, 애플리케이션을 실행하는 환경에 따라 패키징 방식을 선택할 수 있다.

```text
Spring Boot 애플리케이션
        ↓
   빌드 / 패키징
        ↓
 ┌──────┴──────┐
 ↓             ↓
JAR           WAR
 ↓             ↓
직접 실행      외부 Servlet 컨테이너
               ↓
             Tomcat
```

## Member API 실습

`MemberController`를 만들고 회원 목록을 조회하는 API를 추가했다.

```java
@RestController
@RequiredArgsConstructor
public class MemberController {

    private final MemberRepository memberRepository;

    @GetMapping("/members")
    public List<Member> getMembers() {
        return memberRepository.findAll();
    }
}
```

`GET /members` 요청을 보내면 `MemberRepository.findAll()`을 통해 저장된 회원 목록을 조회할 수 있다.

## H2 개발 환경 설정

개발 환경과 테스트 환경을 분리하기 위해 프로파일별 H2 데이터베이스 설정을 추가했다.

### dev

```properties
spring.datasource.url=jdbc:h2:mem:devdb
spring.datasource.username=devu
spring.datasource.password=devp
spring.h2.console.enabled=true
```

### test

```properties
spring.datasource.url=jdbc:h2:mem:testdb
spring.datasource.username=testu
spring.datasource.password=testp
```

개발 환경과 테스트 환경에서 서로 다른 H2 데이터베이스를 사용하도록 구성했다.

# Spring Boot 게시판 실습 마무리

## 23. 기능별 실행 확인 순서

게시판의 각 기능을 구현한 뒤 아래 순서로 URL을 직접 실행하여 동작을 확인한다.

| 순서 | 주소 | 확인 내용 | 로그인 |
|:---:|---|---|:---:|
| 1 | `http://localhost:8080/` | 게시글 목록으로 이동 | 불필요 |
| 2 | `/article/list` | 게시글 목록 / 페이징 | 불필요 |
| 3 | `/article/content?id=1` | 게시글 상세 | 불필요 |
| 4 | `/signup` | 회원가입 | 불필요 |
| 5 | `/login` | 로그인 | 불필요 |
| 6 | `/article/add` | 게시글 작성 | 필요 |
| 7 | `/article/edit?id=1` | 게시글 수정 | 필요 |
| 8 | `/password` | 비밀번호 변경 | 필요 |
| 9 | `/member/list` | 회원 목록 | `ROLE_ADMIN` |

> 게시글 수정과 삭제는 로그인된 상태에서 확인하고, 관리자 기능은 `ROLE_ADMIN` 권한 계정으로 확인한다.

## 24. 꼭 이해해야 할 핵심 흐름

### MVC + Service + Repository 흐름

```text
브라우저
   ↓ 요청
Controller
   ↓
Service
   ↓
Repository
   ↓
Database
```

### 조회 결과 흐름

```text
Database
   ↓
Repository : Entity
   ↓
Service : Entity → DTO
   ↓
Controller : Model에 DTO 저장
   ↓
templates/*.html
   ↓
브라우저 화면
```

### 핵심 포인트

이번 단원의 목적은 HTML 문법 연습이 아니라, Spring Boot 게시판에서 **Controller-Service-Repository-JPA-Security가 어떻게 연결되는지 이해하는 것**이다.

## 25. 반복해서 확인할 개념

| 단계 | 파일 / 작업 | 핵심 내용 |
|:---:|---|---|
| 1 | `@Entity` | 자바 객체와 DB 테이블 연결 |
| 2 | DTO | Entity에서 필요한 데이터만 화면으로 전달 |
| 3 | `JpaRepository` | 기본 CRUD와 메서드 이름 기반 쿼리 |
| 4 | `@Service` | 비즈니스 로직과 DTO 변환 |
| 5 | `@Controller` | URL 요청 처리 + Model + View 이름 반환 |
| 6 | `@Valid` | DTO의 Validation 애노테이션 실행 |
| 7 | `BindingResult` | 검증 오류 저장 및 화면 재표시 |
| 8 | `PasswordEncoder` | 비밀번호 BCrypt 인코딩 / 검증 |
| 9 | `@AuthenticationPrincipal` | 현재 로그인 사용자 정보 주입 |
| 10 | `Pageable` / `Page` | 게시글 / 회원 목록 페이징 |
| 11 | `@Transactional` | 회원 삭제처럼 여러 DB 작업을 한 단위로 처리 |
| 12 | `ROLE_ADMIN` | 관리자 URL 접근 제어 |

## 26. 축소해도 되는 부분

| 단계 | 파일 / 작업 | 핵심 내용 |
|:---:|---|---|
| 축소 1 | Thymeleaf 레이아웃 문법 | templates를 복사하므로 결과 화면 확인 위주 |
| 축소 2 | 페이징 버튼 계산식 | 동작 원리와 결과 확인 위주 |
| 축소 3 | `Page` 객체의 핵심 속성 | 필요한 속성 중심으로 설명 |
| 축소 4 | Validation 애노테이션 전체 목록 | `@NotBlank`, `@Email`, `@Size` 중심 |
| 축소 5 | `UserDetails` 세부 메서드 | username / password / authorities / memberId 중심 |
| 축소 6 | Bootstrap | 디자인 도구라는 정도만 이해 |

반대로 **Entity-DTO 변환, Repository, Service, 로그인 사용자와 memberId 연결, PasswordEncoder, 게시글 CRUD, ROLE_ADMIN, @Transactional**은 핵심 내용이므로 반드시 이해한다.
