## JSP

### JSP란?
- JSP(Java Server Pages) : 자바 서버 페이지
- HTML 문서 안에 Java 코드를 작성하여 동적으로 웹 페이지를 생성하는 방식

### JSP의 초기 구조
- HTML + Java 코드
- 하나의 모듈 안에 Java 코드와 HTML 코드 영역이 혼재
- 이를 **모델 1 아키텍처(Model 1)** 라고 함

### 모델 1 아키텍처의 문제점
- Java 코드와 HTML 코드가 한 곳에 섞여 있음
- 코드가 복잡해짐
- 웹 디자이너와 백엔드 개발자의 협업이 어려움
- 수정할 영역이 서로 얽혀 유지보수가 어려움

## MVC

### MVC란?
- **M(Model) + V(View) + C(Controller)**
- 웹 애플리케이션의 역할을 모델, 뷰, 컨트롤러로 분리하는 구조
- **모델 2 아키텍처(Model 2)**의 대표적인 구조

### MVC의 목적
- 웹 디자이너가 주로 담당하는 **View 영역**과
- 백엔드 개발자가 주로 담당하는 **Controller 영역**을 분리
- 두 영역 사이에서 **Model**을 통해 데이터를 전달

### MVC 동작 방식
1. Controller가 요청을 받음
2. 필요한 데이터를 Model에 저장
3. Controller가 화면(View)의 이름을 반환
4. View가 Model의 데이터를 사용하여 HTML 문서를 생성

예:
```java
model.addAttribute("member", member);
return "member-info";
```

Controller가 `member` 데이터를 Model에 넣고, `member-info`라는 View를 반환하는 구조

## RESTful API

- 경우에 따라 HTML을 응답으로 전달하는 웹 애플리케이션과 구분해서 이해할 수 있음

# Thymeleaf

## Thymeleaf란?
- Spring Boot에서 사용할 수 있는 서버 사이드 템플릿 엔진
- HTML을 기반으로 템플릿을 작성하고, 서버에서 Thymeleaf가 동적으로 HTML을 생성
- HTML 문법과 함께 사용할 수 있어 기존 웹 페이지 구조를 유지하면서 동적인 화면을 만들 수 있음

## Thymeleaf 의존성

`build.gradle`에 Thymeleaf 의존성을 추가

```gradle
implementation 'org.springframework.boot:spring-boot-starter-thymeleaf'
```

현재 학습 프로젝트에는 Thymeleaf와 Spring Web MVC가 함께 구성되어 있음.

# Thymeleaf 기본 문법

## `th:text`

```html
<p th:text="${member.name}">회원 이름</p>
```

형식:

```text
th:text = "${값}"
  문법      화면에 출력할 값
```

- 현재 태그의 텍스트 영역을 지정한 값으로 교체
- 서버에서 렌더링되면 `member.name`의 값이 출력됨

---

## `th:utext`

```html
<p th:utext="#{welcome.description}">Greetings</p>
```

- 현재 태그의 텍스트 영역을 교체
- HTML 태그를 문자열 그대로 해석하여 출력할 때 사용할 수 있음
- `th:text`는 HTML 태그를 문자 그대로 표시하고, `th:utext`는 HTML 태그를 해석한다는 차이가 있음

---

## `th:href`

```html
<a th:href="@{/member}">회원 정보</a>
```

- 현재 태그의 링크 영역을 동적으로 지정

---

## `th:if`

```html
<p th:if="${member.age >= 20}">성인 회원</p>
```

- 조건에 따라 해당 태그의 포함 여부를 결정

---

## `th:each`

리스트의 데이터를 하나씩 꺼내 자식 태그를 반복해서 생성

```html
<tr th:each="member : ${memberlist}">
    <td th:text="${member.id}">1</td>
    <td th:text="${member.name}">윤서준</td>
    <td th:text="${member.email}">naver.com</td>
    <td th:text="${member.age}">14</td>
</tr>
```

Java의 향상된 for문과 비슷한 개념

```java
for (Member member : memberlist) {
    // 반복
}
```

- `${memberlist}` : Model에 담긴 전체 리스트
- `member` : 현재 반복 중인 Member 객체 한 개

따라서 `member.id`, `member.name`처럼 현재 객체의 필드에 접근할 수 있음.

# JPA 연관관계

## `@ManyToOne` 다대일 관계

여러 개의 자식 Entity가 하나의 부모 Entity를 참조하는 관계.

예를 들어 게시글과 회원의 관계에서는:

```text
Member 1  ─────  N Article
```

- 회원 한 명은 여러 게시글을 작성할 수 있음
- 게시글 하나는 한 명의 회원이 작성함
- 따라서 `Article` 입장에서는 `Member`와 **ManyToOne** 관계

```java
@ManyToOne
@JoinColumn(name = "member_id")
private Member member;
```

### 핵심
- 관계의 주인은 일반적으로 **외래 키(FK)를 가지고 있는 쪽**
- 위 예제에서는 `Article.member`가 관계의 주인
- `member_id`가 Article 테이블에 저장되어 어떤 회원이 작성자인지 나타냄

---

## `@OneToMany` 일대다 관계

하나의 부모 Entity가 여러 개의 자식 Entity를 가지는 관계.

위의 회원과 게시글 관계를 `Member` 입장에서 바라보면:

```text
Member 1  ─────  N Article
```

- 회원 한 명이 여러 게시글을 가질 수 있음
- 따라서 `Member` 입장에서는 **OneToMany** 관계

```java
@OneToMany(
        mappedBy = "member",
        cascade = CascadeType.ALL,
        orphanRemoval = true
)
private List<Article> articles;
```

### `mappedBy = "member"`
- 실제 연관관계의 주인이 `Article.member`라는 의미
- `Member`는 외래 키를 직접 관리하지 않음
- `Article.member`와 연결되어 양방향 관계를 구성함

### `cascade = CascadeType.ALL`
- Member에 대한 영속성 작업을 Article에도 전파
- 현재 실습에서는 회원과 연결된 게시글 관리에도 함께 적용됨

### `orphanRemoval = true`
- 부모와의 관계가 끊어진 자식 Entity를 삭제할 수 있도록 함
- 현재 구조에서는 회원 삭제와 연결된 게시글 삭제 관계를 함께 관리하도록 사용

---

## `@ManyToOne` + `@OneToMany` 정리

```text
                Member
                  1
                  │
                  │  @OneToMany
                  │
                  N
                Article
                  │
                  │  @ManyToOne
                  │
                  1
                Member
```

실제 DB 구조는 다음과 같이 이해하면 쉬움.

```text
MEMBER
------
id (PK)

ARTICLE
-------
id (PK)
member_id (FK → MEMBER.id)
```

즉, **DB의 외래 키는 `Article` 쪽에 존재**하고, Java에서는 양쪽에서 서로 참조할 수 있도록 `@ManyToOne`과 `@OneToMany`를 사용한다.

# 메시지 처리와 국제화(i18n)

`messages.properties`에 메시지를 정의:

```properties
welcome=한빛 미디어에 오신 것을 환영합니다
welcome.description=믿고 보는 <b>베스트 상품</b>으로 만족을 더하세요!
```

Thymeleaf에서는 메시지 표현식 `#{...}`을 사용

```html
<p th:text="#{welcome}">Greetings</p>
<p th:text="#{welcome.description}">Greetings</p>
<p th:utext="#{welcome.description}">Greetings</p>
```

- `#{welcome}` : `messages.properties`의 `welcome` 값 사용
- `#{welcome.description}` : `welcome.description` 값 사용
- `th:utext`를 사용하면 `<b>` 같은 HTML 태그도 해석됨

`Greetings`는 HTML에 적어 둔 기본 표시 내용이며, Thymeleaf가 정상적으로 서버 렌더링하면 메시지 값으로 교체됨.

---

# Thymeleaf를 사용하는 이유

- HTML 기반으로 템플릿을 작성할 수 있어 디자이너와 백엔드 개발자가 같은 템플릿을 사용하며 협업하기 좋음
- Thymeleaf 문법이 HTML 속성 형태로 작성되어 구조가 직관적임
- 브라우저에서 템플릿 파일을 직접 열었을 때도 기본 HTML 내용이 표시되어 화면 구조 확인이 가능함
- 서버에서 Thymeleaf로 렌더링하면 `th:*` 속성에 따라 실제 데이터로 변환됨

# 오늘 실습에서 확인한 핵심

## 1. Controller에서 View 이름 반환

```java
@GetMapping("/message/basic")
public String getMessageBasic(){
    return "message/message-basic";
}
```

템플릿이 다음 위치에 있을 때:

```text
src/main/resources/templates/message/message-basic.html
```

Controller는 `templates` 이후의 경로를 기준으로 View 이름을 반환하면 됨.

## 2. Thymeleaf 템플릿 위치

```text
src/main/resources/templates/
```

Thymeleaf View는 일반적으로 `templates` 아래에 둔다.

## 3. Model에 객체 전달

```java
model.addAttribute("member", member);
```

## 4. Model에 리스트 전달

```java
model.addAttribute("memberlist", memberlist);
```

그리고 View에서:

```html
th:each="member : ${memberlist}"
```

으로 반복 출력

## 5. HTML 템플릿과 기본 텍스트

```html
<p th:text="#{welcome}">Greetings</p>
```

`Greetings`는 기본 HTML 텍스트이고, Thymeleaf가 실행되면 `welcome` 메시지 값으로 대체됨.

# 핵심 정리

```text
JSP
→ HTML + Java 코드가 혼재
→ 모델 1
→ 복잡도 증가 / 협업 및 유지보수 어려움

MVC
→ Model + View + Controller
→ 모델 2
→ 데이터와 화면/요청 처리를 분리

Thymeleaf
→ 서버 사이드 템플릿 엔진
→ Controller에서 Model에 데이터 저장
→ View 이름 반환
→ templates 아래 HTML을 Thymeleaf가 렌더링

Controller
→ Model에 데이터 저장
→ View 이름 반환

Thymeleaf View
→ ${...} : Model 데이터
→ #{...} : 메시지
→ th:text : 텍스트 출력
→ th:utext : HTML을 포함한 출력
→ th:href : 링크 설정
→ th:if : 조건 처리
→ th:each : 리스트 반복

JPA 연관관계
→ @ManyToOne : 여러 Entity가 하나의 Entity를 참조
→ @OneToMany : 하나의 Entity가 여러 Entity를 참조
→ @JoinColumn : 외래 키 컬럼 지정
→ mappedBy : 반대편 필드가 연관관계의 주인임을 지정
→ Article.member가 FK(member_id)를 관리
```
