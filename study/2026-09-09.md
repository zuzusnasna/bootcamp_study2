# 2026-09-09 학습 정리

## 회원 정보 수정 문제 해결

### 문제
회원 정보를 수정했을 때 수정 전의 데이터가 그대로 남고, 수정한 내용이 새로운 회원으로 추가되는 문제가 발생했다.

### 원인
수정 Form에서 기존 회원의 `id`가 POST 요청에 함께 전달되지 않으면 JPA는 기존 회원을 식별할 수 없다.

즉, 기존 회원의 PK가 전달되지 않으면 다음과 같이 새로운 Entity로 판단되어 `INSERT`가 발생할 수 있다.

```text
기존 회원
id = 1
   ↓ 수정
id가 전달되지 않음
   ↓
새로운 회원으로 인식
   ↓
INSERT
```

### 해결
`member-edit-form.html`에 기존 회원의 `id`를 hidden input으로 전달하도록 추가했다.

```html
<input type="hidden" name="id" th:value="${member.id}">
```

이 코드는 화면에는 보이지 않지만 수정할 기존 회원의 PK를 POST 요청에 함께 전달하는 역할을 한다.

```text
GET /member/edit?id=1
        ↓
DB에서 id=1 회원 조회
        ↓
Model에 member 저장
        ↓
수정 Form에 member.id를 hidden으로 전달
        ↓
POST /member/edit
        ↓
id=1을 가진 기존 회원 수정
        ↓
UPDATE
```

결과적으로 수정 전 데이터가 별도의 회원으로 남지 않고 기존 회원의 데이터가 수정된 값으로 변경된다.

# Spring Security

## 인증(Authentication)

인증은 **사용자가 누구인지 확인하는 과정**이다.

Spring Security가 로그인 사용자를 확인하려면 애플리케이션이 가지고 있는 사용자 정보가 필요하다.
따라서 `MemberRepository`를 이용하여 회원 정보를 조회하고, Spring Security가 이해할 수 있는 `UserDetails` 형태로 변환해서 반환한다.

전체 흐름:

```text
로그인 요청
   ↓
Spring Security
   ↓
UserDetailsService
   ↓
MemberRepository
   ↓
DB에서 회원 조회
   ↓
Member
   ↓
UserDetails
   ↓
Spring Security가 사용자 정보 확인
```

---

## UserDetailsService 구현

`UserDetailsService`는 Spring Security가 로그인 시 사용자 정보를 조회할 수 있도록 사용하는 인터페이스다.

```java
@Bean
public UserDetailsService userDetailsService(MemberRepository memberRepository) {
    return new UserDetailsService() {
        @Override
        public UserDetails loadUserByUsername(String username)
                throws UsernameNotFoundException {

            var member = memberRepository.findByEmail(username)
                    .orElseThrow(() ->
                            new UsernameNotFoundException("User not found: " + username));

            return User.builder()
                    .username(member.getEmail())
                    .password(member.getPassword())
                    .authorities(member.getAuthority())
                    .build();
        }
    };
}
```

### `loadUserByUsername()`의 username은 무엇인가?

메서드 이름 때문에 반드시 사용자명(username)을 조회하는 것으로 생각할 수 있지만, `username`은 **메서드의 매개변수 이름일 뿐이다.**

현재 실습에서는 로그인 아이디로 이메일을 사용하므로 실제로는 이메일을 전달받는다.

```java
memberRepository.findByEmail(username)
```

즉:

```text
username 변수
      ↓
실제로 전달되는 값 = 이메일
      ↓
findByEmail()
      ↓
Member 조회
```

# 비밀번호 처리

스프링 시큐리티에서 사용자 비밀번호는 매우 민감한 정보이므로 원문 그대로 저장하지 않고 **안전한 방식으로 해시하여 저장**해야 한다.

Spring Security에서는 비밀번호 처리를 위해 `PasswordEncoder` 인터페이스를 제공한다.

## BCryptPasswordEncoder

현재 실습에서는 Spring Security가 제공하는 `BCryptPasswordEncoder`를 사용했다.

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

회원 데이터를 초기화할 때도 BCrypt로 비밀번호를 해시하여 저장한다.

```java
var passwordEncoder = new BCryptPasswordEncoder();

memberRepository.save(Member.builder()
        .name("윤서준")
        .email("Seojun@naver.com")
        .password(passwordEncoder.encode("password"))
        .authority("ROLE_USER")
        .build());
```

즉:

```text
password
   ↓
BCryptPasswordEncoder
   ↓
BCrypt 해시값
   ↓
DB 저장
```

로그인할 때는 입력한 비밀번호를 같은 방식으로 직접 DB 값과 단순 문자열 비교하는 것이 아니라 Spring Security가 `PasswordEncoder`를 이용해 일치 여부를 검증한다.

---

## Base64와 비밀번호 해시의 차이

Base64는 **인코딩 방식**이고, BCrypt는 **비밀번호 검증을 위한 해시 방식**이다.

```text
Base64
원본 → 인코딩 → 문자열
```

Base64는 다시 디코딩할 수 있으므로 비밀번호 보호 목적으로 사용하는 방식이 아니다.

반면 BCrypt는 비밀번호를 해시하여 원문을 그대로 저장하지 않고, 로그인 시 입력값과 저장된 해시가 일치하는지 검증하는 데 사용한다.

# 권한 인가(Authorization)

인가는 **인증된 사용자가 특정 기능이나 페이지에 접근할 수 있는지 확인하는 과정**이다.

실습에서는 회원의 `authority` 값을 이용해 접근 권한을 제한했다.

예:

```java
.requestMatchers("/member/**")
.hasAnyAuthority("ROLE_ADMIN")
```

이는 `/member/**` 경로에 `ROLE_ADMIN` 권한이 있는 사용자만 접근할 수 있도록 설정한다.

예를 들어 초기 데이터가 다음과 같다면:

```text
윤서준  → ROLE_USER
윤광철  → ROLE_ADMIN
```

접근 결과는 다음과 같다.

```text
윤서준
ROLE_USER
   ↓
/member/**
   ↓
접근 거부

윤광철
ROLE_ADMIN
   ↓
/member/**
   ↓
접근 허용
```

# SecurityFilterChain

Spring Security에서 URL별 접근 권한, 로그인, 로그아웃 등의 보안 설정을 구성하는 부분이다.

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) {
    http.authorizeHttpRequests(authorize ->
            authorize.requestMatchers("/", "/home").permitAll()
                    .requestMatchers("/member/**").hasAnyAuthority("ROLE_ADMIN")
                    .anyRequest().authenticated()
    ).formLogin(Customizer.withDefaults())
     .logout(Customizer.withDefaults());

    return http.build();
}
```

### `@Bean`의 중요성

처음 작성한 코드에서는 `SecurityFilterChain` 메서드 앞에 `@Bean`이 빠져 있었다.

```java
public SecurityFilterChain securityFilterChain(HttpSecurity http)
```

이 상태에서는 해당 SecurityFilterChain을 Spring Bean으로 등록하지 못하기 때문에 작성한 URL 접근 제한 설정이 적용되지 않았다.

`@Bean`을 추가하여 해결했다.

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http)
```
