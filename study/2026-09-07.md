## 1. 🌐 Spring Boot REST API 구조

Spring Boot에서는 일반적으로 다음과 같이 계층을 나누어 REST API를 구성한다.

```text
Client
  ↓ HTTP Request
Controller
  ↓
Service
  ↓
Repository
  ↓
JPA / Hibernate
  ↓
Database
```

### 각 계층의 역할

| 계층         | 역할                     |
| ---------- | ---------------------- |
| Controller | HTTP 요청을 받고 응답을 반환     |
| Service    | 비즈니스 로직 처리             |
| Repository | DB 데이터 저장/조회/수정/삭제     |
| Entity     | DB 테이블과 매핑되는 객체        |
| DTO        | 요청과 응답에 사용하는 데이터 전달 객체 |

## 2. 📦 Entity

Entity는 데이터베이스 테이블과 연결되는 객체이다.

```java
@Data
@Entity
@Builder
@AllArgsConstructor
@NoArgsConstructor
public class Member {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    @Column(unique = true)
    private String email;

    private Integer age;
    private String password;
    private boolean enabled;
}
```

### 주요 애너테이션

* `@Entity` : JPA Entity로 지정
* `@Id` : 기본 키 지정
* `@GeneratedValue` : 기본 키 자동 생성
* `@Column(unique = true)` : 해당 컬럼의 중복을 허용하지 않음

## 3. 🔗 Entity 간 관계

게시글 `Article`은 한 명의 회원이 작성한다.

```java
@ManyToOne
private Member member;
```

관계는 다음과 같다.

```text
Member 1 ─────── N Article
```

한 명의 회원은 여러 게시글을 작성할 수 있고, 하나의 게시글은 한 명의 회원에게 속한다.

## 4. 🗂️ Repository

Spring Data JPA에서는 `JpaRepository`를 상속하면 기본적인 CRUD 기능을 사용할 수 있다.

```java
@Repository
public interface MemberRepository extends JpaRepository<Member, Long> {
}
```

### JpaRepository 주요 메서드

| 메서드            | 기능       |
| -------------- | -------- |
| `save()`       | 저장 / 수정  |
| `findAll()`    | 전체 조회    |
| `findById()`   | ID로 조회   |
| `delete()`     | 삭제       |
| `existsById()` | 존재 여부 확인 |

별도의 SQL을 직접 작성하지 않아도 기본 CRUD를 처리할 수 있다.

## 5. 🔍 Query Method

Repository 메서드 이름을 규칙에 맞게 작성하면 조건에 맞는 데이터를 조회할 수 있다.

```java
List<Article> findByMember(Member member);
```

위 메서드는 특정 `Member`가 작성한 `Article` 목록을 조회한다.

```text
findBy + Member
```

Spring Data JPA가 메서드 이름을 분석하여 쿼리를 생성한다.

## 6. 📋 DTO

Entity를 그대로 Controller의 요청/응답에 사용하지 않고 DTO를 사용한다.

### Request DTO

```java
@Data
@Builder
@AllArgsConstructor
@NoArgsConstructor
public class MemberRequest {
    private String name;
    private String email;
    private Integer age;
}
```

### Response DTO

```java
@Data
@Builder
@AllArgsConstructor
@NoArgsConstructor
public class MemberResponse {
    private Long id;
    private String name;
    private String email;
    private Integer age;
}
```

### DTO를 사용하는 이유

```text
Client
  ↓
Request DTO
  ↓
Service
  ↓
Entity
  ↓
Repository
  ↓
DB
```

응답 역시 Entity를 직접 반환하지 않고 Response DTO로 변환한다.

```java
private MemberResponse mapToMemberResponse(Member member) {
    return MemberResponse.builder()
            .id(member.getId())
            .name(member.getName())
            .email(member.getEmail())
            .age(member.getAge())
            .build();
}
```

Entity를 직접 외부에 노출하지 않고 필요한 데이터만 전달할 수 있다는 장점이 있다.

## 7. ⚙️ Service에서 CRUD 처리

Service에서는 Repository를 이용해 실제 데이터를 처리한다.

### 회원 생성

```java
public MemberResponse create(MemberRequest memberRequest) {
    var member = Member.builder()
            .name(memberRequest.getName())
            .email(memberRequest.getEmail())
            .age(memberRequest.getAge())
            .enabled(true)
            .build();

    memberRepository.save(member);
    return mapToMemberResponse(member);
}
```

### 회원 전체 조회

```java
public List<MemberResponse> findAll() {
    return memberRepository.findAll()
            .stream()
            .map(this::mapToMemberResponse)
            .toList();
}
```

### 회원 하나 조회

```java
public MemberResponse findById(Long id) {
    Member member = memberRepository.findById(id)
            .orElseThrow(NotFoundException::new);

    return mapToMemberResponse(member);
}
```

### 회원 수정

```java
public MemberResponse update(Long id, MemberRequest memberRequest) {
    Member member = memberRepository.findById(id)
            .orElseThrow(NotFoundException::new);

    member.setName(memberRequest.getName());
    member.setEmail(memberRequest.getEmail());
    member.setAge(memberRequest.getAge());

    memberRepository.save(member);

    return mapToMemberResponse(member);
}
```

### 회원 삭제

```java
public void delete(Long id) {
    Member member = memberRepository.findById(id)
            .orElseThrow(NotFoundException::new);

    memberRepository.delete(member);
}
```

## 8. 🚨 예외 처리

존재하지 않는 데이터를 조회할 경우 `NotFoundException`을 발생시킨다.

```java
@ResponseStatus(
        code = HttpStatus.NOT_FOUND,
        reason = "Not Found"
)
public class NotFoundException extends RuntimeException {
}
```

Service에서는 다음과 같이 사용한다.

```java
memberRepository.findById(id)
        .orElseThrow(NotFoundException::new);
```

존재하지 않는 회원을 요청하면 HTTP 상태 코드 `404 Not Found`가 반환된다.

```text
존재하지 않는 ID
      ↓
findById()
      ↓
Optional.empty()
      ↓
NotFoundException
      ↓
404 Not Found
```

## 9. 🎮 Controller와 HTTP Method

`@RestController`는 HTTP 요청을 처리하고 결과를 JSON 형태로 반환한다.

```java
@RestController
@RequestMapping("/api/members")
@RequiredArgsConstructor
public class MemberController {

    private final MemberService memberService;
    private final ArticleService articleService;
}
```

### 회원 API

| HTTP Method | URL                 | 기능       |
| ----------- | ------------------- | -------- |
| POST        | `/api/members`      | 회원 생성    |
| GET         | `/api/members`      | 회원 전체 조회 |
| PUT         | `/api/members/{id}` | 회원 수정    |
| DELETE      | `/api/members/{id}` | 회원 삭제    |

## 10. 📝 `@RequestBody`

HTTP 요청의 JSON 데이터를 Java 객체로 변환한다.

```java
@PostMapping
public List<MemberResponse> post(
        @RequestBody List<MemberRequest> memberRequests) {

    return memberService.createBatch(memberRequests);
}
```

예를 들어 다음 JSON을 요청하면:

```json
[
  {
    "name": "홍길동",
    "email": "hong@test.com",
    "age": 20
  }
]
```

Spring이 JSON 데이터를 `MemberRequest` 객체로 변환한다.

```text
JSON
 ↓
@RequestBody
 ↓
MemberRequest
```

## 11. 🔎 `@PathVariable`

URL의 `{id}` 값을 Java 변수로 전달받는다.

```java
@PutMapping("/{id}")
public MemberResponse updateMember(
        @PathVariable Long id,
        @RequestBody MemberRequest memberRequest) {

    return memberService.update(id, memberRequest);
}
```

```text
PUT /api/members/1
                ↑
              id = 1
```

## 12. 🔍 `@RequestParam`

Query String의 값을 전달받는다.

```java
@GetMapping
public List<ArticleResponse> getByMember(
        @RequestParam(
                name = "memberId",
                required = false
        ) Long memberId) {

    if (memberId == null) {
        return articleService.findAll();
    }

    return articleService.findByMemberId(memberId);
}
```

### 전체 게시글 조회

```text
GET /api/articles
```

### 특정 회원의 게시글 조회

```text
GET /api/articles?memberId=1
```

즉,

```text
memberId 없음
    ↓
전체 게시글 조회

memberId 있음
    ↓
해당 회원의 게시글 조회
```

## 13. 📰 Article API

게시글은 회원과 연결되어 있다.

| HTTP Method | URL                          | 기능            |
| ----------- | ---------------------------- | ------------- |
| POST        | `/api/members/{id}/articles` | 특정 회원의 게시글 작성 |
| GET         | `/api/articles`              | 전체 게시글 조회     |
| GET         | `/api/articles?memberId=1`   | 특정 회원 게시글 조회  |
| GET         | `/api/articles/{id}`         | 게시글 하나 조회     |
| PUT         | `/api/articles/{id}`         | 게시글 수정        |

### 게시글 작성

```java
public ArticleResponse create(
        Long memberId,
        ArticleRequest articleRequest) {

    Member member = memberRepository.findById(memberId)
            .orElseThrow(NotFoundException::new);

    Article article = Article.builder()
            .title(articleRequest.getTitle())
            .description(articleRequest.getDescription())
            .member(member)
            .build();

    articleRepository.save(article);

    return mapToArticleResponse(article);
}
```

먼저 `memberId`로 회원을 조회한 다음 Article에 회원을 연결한다.

```text
memberId
   ↓
Member 조회
   ↓
Article 생성
   ↓
member 연결
   ↓
Article 저장
```

## 14. ✅ `@ResponseStatus(HttpStatus.CREATED)`

게시글 생성 API에는 `201 Created`를 사용한다.

```java
@PostMapping("/{id}/articles")
@ResponseStatus(HttpStatus.CREATED)
public ArticleResponse postArticle(...) {
    ...
}
```

### HTTP 상태 코드

| 상태 코드 | 의미               |
| ----- | ---------------- |
| 200   | 요청 성공            |
| 201   | 리소스 생성 성공        |
| 404   | 요청한 리소스를 찾을 수 없음 |

회원 생성, 게시글 생성 등 **새로운 리소스를 생성하는 경우 201 Created**를 사용하는 것이 REST API에서 일반적이다.

## 15. 🧩 Lombok

현재 프로젝트에서는 Lombok을 이용해 반복적인 코드를 줄였다.

```java
@Data
@Builder
@AllArgsConstructor
@NoArgsConstructor
```

### 주요 애너테이션

| 애너테이션                      | 기능                                                    |
| -------------------------- | ----------------------------------------------------- |
| `@Data`                    | Getter, Setter, `toString`, `equals`, `hashCode` 등 생성 |
| `@Builder`                 | Builder 패턴 제공                                         |
| `@AllArgsConstructor`      | 모든 필드를 받는 생성자 생성                                      |
| `@NoArgsConstructor`       | 기본 생성자 생성                                             |
| `@RequiredArgsConstructor` | 필요한 필드를 받는 생성자 생성                                     |

특히 `@RequestBody`로 JSON을 DTO로 변환할 때 기본 생성자가 필요할 수 있기 때문에 Request DTO에 `@NoArgsConstructor`를 사용한다.

## 16. 🔄 Transaction

회원 여러 명을 한 번에 생성하는 메서드에 `@Transactional`을 적용했다.

```java
@Transactional
public List<MemberResponse> createBatch(
        List<MemberRequest> memberRequests) {

    return memberRequests.stream()
            .map(this::create)
            .toList();
}
```

트랜잭션은 여러 DB 작업을 하나의 작업 단위로 묶어 처리한다.

```text
createBatch()
     ↓
┌─────────────────┐
│   Transaction   │
│                 │
│ 회원 1 저장     │
│ 회원 2 저장     │
│ 회원 3 저장     │
└─────────────────┘
     ↓
 Commit / Rollback
```

## 17. ⏱️ JPA Auditing

Article에서는 생성일과 수정일을 자동으로 관리한다.

```java
@EntityListeners(AuditingEntityListener.class)
public class Article {

    @CreatedDate
    private Date created;

    @LastModifiedDate
    private Date updated;
}
```

그리고 애플리케이션에서 Auditing을 활성화한다.

```java
@SpringBootApplication
@EnableJpaAuditing
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

### 주요 애너테이션

* `@CreatedDate` → Entity 생성 시간 자동 기록
* `@LastModifiedDate` → Entity 수정 시간 자동 기록
* `@EnableJpaAuditing` → JPA Auditing 활성화
* `@EntityListeners(AuditingEntityListener.class)` → Auditing 이벤트 연결

## 20. 🧠 REST API 설계 정리

REST API에서는 URL은 **리소스**, HTTP Method는 **행위**를 나타내도록 설계한다.

예를 들어 회원 리소스가 있다고 하면:

```text
POST   /api/members       → 생성
GET    /api/members       → 전체 조회
GET    /api/members/1     → 특정 회원 조회
PUT    /api/members/1     → 수정
DELETE /api/members/1     → 삭제
```

게시글도 같은 방식으로 구성할 수 있다.

```text
POST   /api/articles      → 게시글 생성
GET    /api/articles      → 전체 조회
GET    /api/articles/1    → 특정 게시글 조회
PUT    /api/articles/1    → 수정
DELETE /api/articles/1    → 삭제
```

현재 프로젝트에서는 회원과 게시글의 관계를 고려하여 다음과 같이 회원 기준 게시글 작성 API도 구성했다.

```text
POST /api/members/1/articles
```
